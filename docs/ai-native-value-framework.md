# Hotel Agent OS：AI Native 与四条价值线

## 核心原则

系统理解顾客的意图，不要求顾客记住固定指令。顾客可以自然地描述入住、订单、房型、押金或设备问题，AI负责提取必要信息并提出业务动作；确定性业务程序负责权限、状态、参数、幂等和回执校验。

```text
顾客自然表达
  ↓
意图识别 + 参数提取 + 置信度
  ↓
缺失信息追问 / 歧义澄清
  ↓
业务安全网关
  ↓
PMS、数据库、支付、公安浏览器或设备适配器
  ↓
回执与审计
  ↓
自然语言反馈
```

AI不能直接改价、跳过登记、任意选择冲突订单或直接指定房卡权限。订单、房态、身份、金额、支付和设备状态必须通过正式接口精确读取。

## 意图审计

每次理解至少记录：

- 脱敏后的顾客表达；
- 识别出的意图；
- 置信度；
- 提取参数；
- 建议的业务动作；
- 安全网关判断；
- 工具回执与最终状态。

完整手机号、身份证号码、证件照片、支付凭据和有效公安字段不得写入通用审计日志。低置信度、参数缺失或多笔订单冲突时必须继续询问，不能替顾客猜测。

## 四条价值线

| 价值线 | 目标 | 首期指标 |
| --- | --- | --- |
| 收益 | 提升入住转化与增值成交 | RevPAR、ADR、入住率、房型升级率、增值收入 |
| 人力 | 减少前台和房务重复工时 | 单笔人工分钟数、自动完成率、人工介入率、节省工时 |
| 响应 | 提供7×24多语言服务 | 首段语音P95、完整办理时间、可用率、多语言成功率 |
| 合规 | 让每个动作有据可查 | 审计覆盖率、非法跳转、重复登记/发卡、敏感数据泄漏 |

RevPAR提升必须通过上线前后同期对照或A/B测试验证。演示环境只展示指标结构；真实经营数据接入PMS和财务系统后才能形成生产结论。

## 演示验收

- 顾客用不同说法表达同一需求时，系统能对齐到同一意图；
- 缺手机号后四位时主动追问；
- 早餐、停车、押金和退房问题只回答政策，不误触发入住；
- 房卡进度只查询原命令，不重复发卡；
- 管理后台能看到脱敏的“表达→意图→置信度→动作”链路；
- 四条价值线明确区分演示指标、目标值和待接生产数据；
- 所有关键业务副作用继续由状态机和确定性接口执行。
