# 管理员认证与权限（第一阶段）

管理后台不再因为点击按钮就直接打开。进入后台必须先建立管理员会话，服务端通过 HttpOnly、Secure、SameSite=Strict Cookie 识别操作者；浏览器端不能自行伪造角色。

## 角色

- `owner`：所有后台权限。
- `manager`：订单、房态、换房、入住/退房、设备和仿真故障管理。
- `frontdesk`：订单、房态、换房、入住/退房。
- `housekeeping`：只读房态。

权限判断在接口层执行。前端隐藏按钮只是体验优化，不是安全边界。

## 演示账号

首次启动会自动创建四个演示账号：`admin-owner-demo`、`admin-manager-demo`、`admin-frontdesk-demo`、`admin-housekeeping-demo`。演示口令为 `hotel-demo-2026`，仅用于本地演示；生产部署前必须替换口令、停用演示账号并接入酒店自己的账号目录。

## 会话与审计

会话默认 8 小时，服务端只保存会话令牌哈希，不保存明文令牌。登录成功、登录失败、权限拒绝和退出都会写入 `admin_audit_events`，日志不记录密码、完整手机号或身份证号。

管理员工具先经过 `lib/admin-tools.ts` 的 Zod 契约和权限映射，再由业务 API 执行；模型不能 import 数据库，也不能直接改表。后续换房等高风险动作应继续采用“准备 → 展示脱敏信息 → 明确确认 → 执行”的两阶段工具流程。
